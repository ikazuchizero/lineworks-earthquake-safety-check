## 2. 管理者への依頼（画面共有しながら読み上げる）

> LINE WORKS 側で3つお願いします。
>
> **① Bot を会社の管理画面に追加**
> 管理画面 → 上部メニュー「サービス」→「Bot」→「Bot追加」→ 対象のBotを選んで追加。
> 使用範囲は「全て」にしてください（「制限」だとメンバーの連絡先にも出ません）。
>
> **② 安否確認用のグループトークを作成して Bot を招待**
> 1対1のトークにはBotを追加できないので、グループトークでお願いします。
> 「招待」→「Bot」タブ → 対象のBotを選択。
>
> **③ そのルームの channelId を教えてください**
> Bot から API で取得します。ルーム名だけで大丈夫です。
>
> あわせて、**古いPHP版のcronが残っていれば停止**をお願いします（二重通知になります）。

### 管理者がつまずいたときの案内

| 症状 | 案内 |
|---|---|
| 「Bot が一覧にない」 | Developer Console に Bot があるか確認 → 管理画面の「Bot追加」をやり直す |
| 「1対1トークに招待できない」 | グループトークを作ってもらう |
| 「使用範囲」の選択肢 | まず「全て」で。あとから絞れる |

> **順番の要点**
> - `initializeNotificationBaseline` → `setupTriggers` は間を空けない（その間の地震が通知されない）
> - 旧PHP版の停止はベースラインの**直前**（停止と再開の隙間を最小化）
> - `NOTIFY_SCALE` は `setupTriggers` より前に本番値へ（`0` のままだと震度1でも通知）

> **新規構築（既存のPHP版が動いていない）場合**
> 19:20 の「旧PHP版の停止」はスキップし、そのまま 19:22 のベースラインへ進んでください。
> 切り戻しも「トリガーを2つ削除」だけで済み、元の更地に戻ります。
> 失敗したら翌日に `setupTriggers` から再開できます（`initializeNotificationBaseline` は
> トリガーが無い状態なら何度でも実行できます）。

| キー | 本番値の例 | 注意 |
|---|---|---|
| `SPREADSHEET_ID` | 本番シートのID | 所有者は GAS と同じアカウント |

| `QUIET_HOURS_*` | `0`〜`6` | 運用に合わせて |

## 6. 切り戻し（問題が出たとき）

1. GAS エディタ左「トリガー」→ `checkAndNotifyEarthquake` / `writeHourlyHealthCheck` を削除（**通知が止まる**）
2. 旧PHP版の cron を再開
3. 原因調査（`地震ログ` / `ヘルスチェック` / 実行数）

> 通知を止めるだけなら、`NOTIFY_SCALE` を `70`（震度7のみ）に上げる方法もありますが、
> 完全停止はトリガー削除が確実です。

## 7. 当日のトラブル早見表

| 症状 | 対処 |
|---|---|
| `User has not enabled the Apps Script API` | 本番アカウントで <https://script.google.com/home/usersettings> を ON、数分待つ |
| `403`（送信） | Bot の管理画面追加 → ルーム招待 → `SERVICE_ACCT` が同アカウントか → `ROOM_ID` が channelId か |
| Bot が招待一覧に出ない | 管理画面「サービス」→「Bot」→「Bot追加」。1対1ではなくグループトーク |
| `Pushed 0 files` | `--rootDir src` を付けているか、`ls src` が28か |
| `NG triggers` | `setupTriggers` 未実行、または間隔の保存値が古い |
| ベースラインが拒否される | 既にトリガーが動いている。トリガー削除 → 実行 → 再登録 |
| `429 error 1015` | P2PQuake のレート制限。10分間隔で運用し、頻発なら15/30分へ |
| 同じ地震で2通届く | `状態` シートの該当行を確認（キーが日時型になっていないか） |
